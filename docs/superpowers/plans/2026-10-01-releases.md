# Releases Table and Release Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/releases/` table of every Rootprint version and a prerendered page per release, each built from one mdsvex markdown file.

**Architecture:** Each release is `src/content/releases/X.Y.Z.md` (frontmatter + AI-written announcement + verbatim changelog). `$lib/releases.ts` globs those files with `import.meta.glob`, merges in a hard-coded list of 0.1.x tag-only versions, and sorts everything by version. The table page, the `[version]` route, and the sitemap all read from that one module.

**Tech Stack:** SvelteKit 2, Svelte 5 runes, `@sveltejs/adapter-static`, mdsvex 0.12, Bun, Prettier defaults.

**Spec:** `docs/superpowers/specs/2026-10-01-releases-design.md`

## Global Constraints

- Only new dependency: `mdsvex` (dev), installed with `bun add -d mdsvex`.
- Release URLs: `/releases/` and `/releases/X.Y.Z/` (no `v`, trailing slash; root layout sets `trailingSlash = "always"`).
- Frontmatter has exactly three fields: `date` (quoted `"YYYY-MM-DD"`), `title`, `summary`. The version is the filename.
- Dates render as stored, ISO `2026-09-22`. No `Intl` date formatting.
- Changelog sections are pasted verbatim under `## Changelog`.
- No breaking-change badges or fields anywhere. The only badge is `latest`.
- Styling: tokens from `src/app.css` only (`--base-*`, `--hairline*`, `--primary*`), zero radius, no shadows, green only as accent.
- TS strict, `<script lang="ts">`, Svelte 5 runes, Prettier defaults (`bun run format`).
- No automated test framework in this repo (AGENTS.md). Verify with `bun run check`, `bun run build`, and the build-output assertions in each task.
- Git: do not run `git add`/`git commit` unless the user explicitly asks. When asked, single-sentence message, no AI attribution.

## Review Focus

1. A release file with an unquoted date, missing `title`/`summary`, or a filename like `v0.4.5.md` → the build fails with a message naming the file (not a silent tag-only row). Pinned in Task 1, Step 7.
2. Versions with multi-digit parts (0.1.10 vs 0.1.9) → numeric order, 0.1.11, 0.1.10, 0.1.9. Pinned in Task 2, Step 3.
3. Client-side navigation from one release page to the previous one (prev/next links) → heading and body both switch to the new release. Pinned in Task 5, Step 3.
4. Long inline code (`/api/settings/auth/oidc/credentials`) and code blocks at 390px → no horizontal page scroll. Pinned in Task 5, Step 3.
5. Header nav at 780px with the added "Releases" link → links stay on one row. Pinned in Task 5, Step 3.

- [ ] **Step 3: Create `src/lib/releases.ts`**

```ts
import type { Component } from "svelte";
import { githubUrl } from "$lib/links";

export interface Release {
  version: string;
  date: string;
}

export interface ReleasePage extends Release {
  title: string;
  summary: string;
}

const metadata = import.meta.glob<Omit<ReleasePage, "version">>(
  "/src/content/releases/*.md",
  { eager: true, import: "metadata" },
);
// Lazy so the table page doesn't ship every release body.
const bodies = import.meta.glob<Component>("/src/content/releases/*.md", {
  import: "default",
});

const newestFirst = (a: Release, b: Release) =>
  b.version.localeCompare(a.version, undefined, { numeric: true });

export const pages: ReleasePage[] = Object.entries(metadata)
  .map(([path, meta]) => {
    const version = path.slice(path.lastIndexOf("/") + 1, -".md".length);
    if (
      !/^\d+\.\d+\.\d+$/.test(version) ||
      !meta?.title ||
      !meta.summary ||
      !/^\d{4}-\d{2}-\d{2}$/.test(String(meta.date))
    ) {
      throw new Error(
        `${path}: needs an X.Y.Z.md filename and frontmatter with title, summary, and a quoted "YYYY-MM-DD" date`,
      );
    }
    return {
      version,
      date: meta.date,
      title: meta.title,
      summary: meta.summary,
    };
  })
  .sort(newestFirst);

// 0.1.x shipped before the changelog was kept, so these rows link to GitHub tags.
const tagOnly: Release[] = [
  { version: "0.1.11", date: "2026-04-13" },
  { version: "0.1.10", date: "2026-04-07" },
  { version: "0.1.9", date: "2026-04-07" },
  { version: "0.1.8", date: "2026-03-28" },
  { version: "0.1.7", date: "2026-03-26" },
  { version: "0.1.6", date: "2026-03-26" },
  { version: "0.1.5", date: "2026-03-26" },
  { version: "0.1.4", date: "2026-03-25" },
  { version: "0.1.3", date: "2026-03-25" },
  { version: "0.1.2", date: "2026-03-24" },
  { version: "0.1.1", date: "2026-03-24" },
  { version: "0.1.0", date: "2026-03-24" },
];

export const releases: Release[] = [...pages, ...tagOnly].sort(newestFirst);
export const latest = releases[0];

export const hasPage = (release: Release): release is ReleasePage =>
  "title" in release;

export const tagUrl = (version: string) =>
  `${githubUrl}/releases/tag/v${version}`;

export const loadBody = (version: string) =>
  bodies[`/src/content/releases/${version}.md`]();
```

- [ ] **Step 5: Create `src/routes/(marketing)/releases/[version]/+page.ts`**

```ts
import { error } from "@sveltejs/kit";
import { loadBody, pages, releases } from "$lib/releases";
import type { EntryGenerator, PageLoad } from "./$types";

export const entries: EntryGenerator = () =>
  pages.map(({ version }) => ({ version }));

// Universal load: a server load can't pass the mdsvex component to the page.
export const load: PageLoad = async ({ params }) => {
  const index = pages.findIndex(({ version }) => version === params.version);
  if (index === -1) error(404, "Release not found");
  const release = pages[index];

  return {
    release,
    body: await loadBody(release.version),
    newer: pages[index - 1],
    older: pages[index + 1],
    previousVersion: releases[releases.indexOf(release) + 1]?.version,
  };
};
```
